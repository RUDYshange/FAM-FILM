Turnoverone call sheet, and it's yours

A call sheet is not a document. It's a live answer to one question — where do I need to be, and has that changed since I last looked? Turnover replaces the nightly PDF drop with a personalised link each person opens on their phone, and a console the PM runs the day from.

3documents

Call sheet, shooting schedule, production booklet — sent as separate attachments to roughly thirty people. Each one restates the same call times, so each one is a chance to disagree with the others.

17:37sent

The night before a 07h00 unit call. Anyone already asleep, driving, or out of data finds out at the gate. There is no way to know who has actually read it.

On one shoot day: lunch listed as 15h00 and 15h15; the minimum temperature given as 2°, 3° and 4°; the gear check dated both 7 August and 11 August. Nobody made a mistake. The files just stopped agreeing.

What I'd actually build first

and what I'd leave out

The three ideas you listed are one product. The client portal and the check-in portal are views onto the same schedule — building them as separate apps is how this dies. Ship the smallest thing a PM would use unsupervised.

FIRST

Import, don't author

No PM will retype a call sheet into your app. Version one takes the Excel or PDF they already make and turns it into personalised links.

  • Upload → parse the movement order table
  • One row per person, one link per person
  • Delivered by WhatsApp, no install
THEN

Read receipts

This is the feature a production manager will pay for on day one, because it removes a job she currently does by phoning people.

  • Opened / confirmed per person
  • One-tap nudge to the gaps
  • Timestamped record if a call is disputed
LATER

Live changes

Only once people trust the link enough to check it on set. Until then a delay push is noise.

  • Shift a block, notify only who's affected
  • Minor-hours and meal-penalty clocks
  • Read-only agency view

Demo data is fictional — invented brand, invented crew, no script lines, no phone numbers. Production paperwork carries a confidentiality clause and real cast contact details, so a portfolio prototype should never be built on the live document. Keeping it clean also makes it a better pitch: the shape of the problem is the interesting part, not whose shoot it was.
